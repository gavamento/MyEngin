# エンジン機能・ABI の自然言語検索 (構想メモ)

**現在地: 検討のみ。コードは 1 行も書いていない。採否も未決定。**
2026-09-08 の会話で出た「このエンジン用に最適化した小型 LLM を載せて、機能や ABI を
自然言語で検索できるようにする」という案の評価をそのまま残したもの。
着手するときは §7 の「未決の判断」から読むこと。

---

## 1. 依頼の分解

「LLM を実装する」と「自然言語で検索できる」は別問題。依頼には 2 つ入っている。

| | 中身 | LLM 要否 |
|---|---|---|
| **(A) 検索** | 「音が壁で減衰するやつ」→ `AcousticAudio` / `ShapeAcousticSpatial` / `--acoustic-demo` を出す | **不要** (索引 + 埋め込み or BM25) |
| **(B) 生成** | 見つけたものを日本語で説明する / 使い方のコードを書く | 必須 |

**(B) こそ小型モデルが最も苦手**。1B 級は `kNetMaxSpeculation` や
「`MYE_API_VERSION` v16 = 110 スロット」のような固有語彙を平気で捏造する。
このリポは `Interop.cs` が**位置ベースのミラーで実行時の版検証が無い**ので、
「それっぽいが嘘の ABI 名」の害が一般的なプロジェクトより明確に大きい。
→ (B) は優先度を下げる。

## 2. このリポは索引の材料が異常に揃っている (最大の追い風)

実測 (2026-09-08 時点):

- `src\Engine\Core\Components.cpp` の `MYE_JP("表示名", MYE_FIELD(...))` が **436 件**
  = **フィールド単位で日本語表示名つきのメタデータが既にある**
- `src\Engine\Core\LocalizationTable.inl` **1269 行** — `MYE_STR(id, en, ja)` の
  **対訳コーパスが既製品として存在する**
- `src\Shared\EngineAPI.h` **110 スロット (v16)**、
  `RegisterBuiltinComponents()` **50 コンポーネント (TypeId 付き)**
- CLI フラグ約 60 種 — CLAUDE.md に説明つきで既に列挙済み
- `engine_spec.md` 258KB / `docs\adr\` 17 本 / README 35KB
- ソース 526 ファイルが「**なぜそうなっているか・踏んだ罠**を日本語で書く」規約
  = 検索対象としての質が普通のコードベースより高い

**索引を作るコストがほぼゼロ**。しかも `tools\gen_project_files.ps1` と同じ
「生成物」の枠にきれいに収まる。

## 4. 段階案

### S0 — 索引ジェネレータだけ (LLM ゼロ)

`tools\gen_engine_index.ps1` → `cache\engine_index.json`。
component / field / abi / cli / l10n / adr のセクションを持つ。

副産物が 3 つ効く:
1. エディタの検索の土台
2. **Claude Code が読める索引** (= 今すぐ効く)
3. 「CLAUDE.md に載っている CLI フラグ ⇄ 実際の argv パーサ」「ADR 番号の欠番」
   のような**規則の機械検査** — `tools\check_rules.ps1` の自然な延長線上

### S1 — エディタ内検索パレット (BM25 + 日英同義語)

「霧」→ `FogVolume` / `--fog-demo` / golden 15 枚目 / M57。
ここまでで実用の 7〜8 割。追加バイナリ 0。

### S2 — 埋め込みモデルで semantic 検索

ONNX Runtime CPU + multilingual-e5-small 級 (**日本語必須なので多言語モデル一択**。
int8 で約 120MB)。**「自然言語で」の本体はここ**。単発クエリなら CPU で数 ms〜数十 ms。

### S3 — 生成 (回答文を作る)

**推奨しない。** やるなら S0 の索引を **MCP サーバとして外に出して
Claude Code / Claude Desktop に食わせる**方が、桁違いに安くて正確。
`tools\collab` の Rust + NDJSON と同じ枠で作れる。

## 5. このリポ特有の制約 — 着手するなら最初に決めること

1. **sim に絶対入れない。** `check_rules.ps1` の規則 12 (Source Control の
   Editor 層封じ込め) と**同型の封じ込めを規則 13 として先に書く**。
   後から足すと必ず漏れる。
2. **`--selftest` と CI から完全に外す。** モデルが無ければ窓が「利用不可」に
   なるだけ (`MyeCollab.dll` と同じ縮退)。CI に GB 級を落とさせない。
3. **モデルを git に入れない。** このリポの版管理バイナリは `tests\golden\*.png` だけ。
   `cache\models\` に置いて gitignore + `tools\fetch_model.ps1`
   (= `build_collab.bat` の cargo と同じ「無ければ機能が利用不可になるだけ」)。
4. **推論は別プロセスに出す。** エディタ実行中は DLL を上書きできない罠
   (`MyeScripting.dll` / `MyeCollab.dll`) を確実に踏む。Source Control の
   NDJSON パイプという**検証済みの配管がすでにある**ので、これを型として使い回すのが安い。
5. **回帰テストの設計。** 検索結果は sim 外なのでビット一致は不要。ただし
   `collab_verify.bat` 型の期待 NDJSON をやるなら、**BM25 層だけを完全固定**し、
   埋め込み層は **top-k の集合一致 (順序不問)** で見る、という切り方が要る
   (温度 0 でも CPU/GPU で数値は揃わない)。
6. **ライセンス。** llama.cpp / ONNX Runtime は MIT だが**重みは別ライセンス**。
   e5 は MIT、Qwen は Apache-2.0。学校提出物なら確認が要る。

## 6. 懸念

- 学習コストより**維持コスト**。索引ジェネレータはソース構造に依存するので、
  `MYE_JP` の書式を変えた瞬間に静かに壊れる。
  →「索引の件数が N 未満なら fail」程度の下限チェックが `check_rules.ps1` に要る。
- 「エンジンに LLM を載せた」は話として面白いが、**エンジンの価値には直結しない**。
  三校企画 / HAL Collector の文脈で審査に効くのは決定論・リプレイ・音響の方。
  時間配分は意識すること。ただし S0 は数時間規模なので費用対効果は良い。
