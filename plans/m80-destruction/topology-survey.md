前提が変わった状態 (断面の三角形分割は libtess2、ボクセル化は surface nets、凸包生成の無限ループは
修正済み) で、破片の位相的な閉じ (頂点の共有) がどの程度実現可能かを計測した記録。
結論は `docs/adr/ADR-021-fracture-destruction.md` の「位相的な閉じの再調査」に転記済み。

## 1. 計測方法

`BakeFracture` の出力 (破片ごとの `outer` + `cap`) を結合し、位置のビット一致 (exact) で
溶接してから、無向辺の使用回数を数える (`FractureMesh.cpp` の `CheckClosedMesh` と同じ
アルゴリズムを、破片ごと・出所 (outer/cap) を跨いだ内訳集計のために独立実装した一時プローブで
計測。使用回数 1 = 境界辺、3 以上 = 非多様体辺、2 だが同じ向き 2 回 = 向き不一致。3 種の合計を
「位相的な境界辺の数 (defect edges)」と呼ぶ)。

内訳 (外側面と蓋の継ぎ目 = 丸めのずれ / 蓋どうしの継ぎ目 = T字接合) は、位置を粗く量子化
(格子幅 ε) してから同じ溶接・辺カウントをもう一度行う「粗溶接」との差分で推定した:
- 丸めのずれ (ulp 単位の差) は ε ≈ 1e-4 (対象物のスケール ~1〜2 に対して十分小さいが ulp より
  十分大きい) で解消される。`defect(exact) − defect(ε=1e-4)` を「丸めのずれ」の推定値とする
- T字接合は、輪郭の途中に真に新しい頂点が挿入される位相的な分割であり、ε=1e-4 程度の量子化では
  解消しない (端点どうしが元々 ε 以上離れているため)。`defect(ε=1e-4)` を「T字接合 + その他」の
  残存推定値とする
- ε の妥当性は 1e-6 / 1e-4 / 1e-2 の 3 段階で確認した。1e-2 は箱・トーラス・実アセットのいずれでも
  defect 数が増える方向にぶれた (無関係な頂点まで誤って溶接してしまう = 過剰量子化の兆候)。
  1e-4 は 1e-6 よりも一貫して小さく、1e-2 のような増加は見られない — 丸めのずれの分だけを
  吸収する帯として妥当と判断した

計測は一時プローブ (`FractureSelfTest.cpp` / `FractureSkinSelfTest.cpp` に一時追加し、
`--selftest` で走らせて記録後に revert。最終コミットには含まれない) で行った。

## 3. 読み取れること

- 多破片 (16〜32) の合成物では、T字接合 (蓋どうしの継ぎ目) が defect の 55〜66% を占め、
  丸めのずれ (外側面と蓋の継ぎ目) より**大きい**カテゴリになる。設計時の想定 (両方が残る) は
  正しかったが、量的には T字接合側が支配的
- 破片数が少ない実アセット (2〜3 破片) では、境界が単純な 2 分割中心になるため T字接合の
  機会がほとんど無く、defect のほぼ全てが丸めのずれになる。これは「T字接合は 3 個以上の
  Voronoi セルが 1 点に接する配置で発生する」という理解と整合する
- ε=1e-2 で箱・トーラス・CesiumMan のいずれも defect 数が増加に転じており、対象物のスケール
  (~1〜2) に対して量子化が粗すぎると無関係な頂点まで誤って溶接し、新しい非多様体/向き不一致を
  作ることが確認できる。ε の選定は対象物のスケールに依存する脆い操作であり、恒久的な判定手段
  としては採用できない (今回はあくまで内訳を推定するための調査用の道具)

## 4. 方式の評価 (実装しない。調査のみ)

sub-15.md が例示した 2 方式は、コードを読んだ結果 **同じ根本原因 (3 箇所の独立したクリップ経路が
それぞれ別の浮動小数点演算を行い、境界点が一致しない) に対する 2 つの側面**だと分かった
(`FractureBake.cpp`):
- 外側面は「ソース三角形ごとに、自分の候補面すべてで**順に**三角形単位クリップ」(:509-513)
- 蓋は「シード対 (i,j) ごとに `CutMeshByPlane` で元メッシュを 1 回切ってから、i と j の
  **他の候補面の和集合**でさらに三角形単位クリップ」(:481-482, :616)

外側面と蓋は別の関数・別のクリップ順序を通るため、同じ幾何学的な交点でも異なる浮動小数点演算
列を通り、ビット同一にならない (丸めのずれ)。さらに、蓋どうしの継ぎ目は「同じ Voronoi セル辺を
異なる隣接ペア (i,j) と (i,k) がそれぞれ独立に (他の候補面で) クリップする」ため、一方が
その辺を分割し他方が分割しない、という食い違い (T字接合) が生まれる。

これは、2 つの提案方式が実質 1 つの再設計に収束することを意味する:

**方式: 候補面どうしの交点を破片ごとに事前計算し、3 箇所のクリップ (外側面・蓋の 1 回切り・
蓋の再クリップ) が全て同じ点集合を参照する。**
- 規模の見積もり: 候補面のペア交差 (破片の Voronoi セルの辺) を列挙する新しい前処理
  (セル多面体の構築 (`FractureBake.cpp` 2. 節) と重なる範囲がある)、交点を正準キー
  (平面ペアの id の組、または (元の辺 id, 平面 id) の組) で引けるキャッシュ、3 箇所の
  クリップ関数をそのキャッシュ経由へ差し替える改修が要る。`FractureBake.cpp` の該当範囲
  (2〜3 節、断面生成を含め約 600〜900 行) に触れる規模になり、新規・変更コードは
  概算 400〜800 行 (前処理 150〜250 行、キャッシュ+差し替え 150〜300 行、SelfTest の
  期待値更新と新規回帰 100〜250 行)
- 決定性への影響: 交点の正準キーをどう選ぶかで決定論の作り直しが必要 (今の「三角形の
  クリップ順」に依存しない、平面 id の組など安定なキーにする必要がある)。実装自体は
  既存の「演算順固定・ハッシュ走査に依らない」契約を維持できる設計だが、**`.mfrac` の
  出力バイト列は必ず変わる** (境界点の座標が変わるため) — 版を v2 に上げ、v1 読み込みの
  後方互換と、box/L字/トーラスの digest 値の全面的な再ベースラインが要る
- 下流の利点: 実行中の再分割 (B) は、破片をもう一度切るときに「隣接する破片の断面と
  再度ビット一致する」ことが前提になりやすい (再分割後も接着グラフや凸包生成が安定した
  入力を必要とする)。位相的に閉じたメッシュにしておけば、その前提を満たしやすくなる
- リスク: この領域 (`FractureBake.cpp` の断面生成) は sub-02 で 3 ラウンド、sub-13/sub-14で
  それぞれ 1 サブ分の再設計が入っており、**同じ箇所の 3 回目以降の大規模改修**になる。
  過去の再設計はいずれも「単純多角形/耳切りの前提が実データで壊れる」という失敗から始まって
  おり、位相的な閉じの実装も新しい失敗モード (交点キャッシュの祖先探索ミスなど) を持ち込む
  リスクが高い

## 5. 結論 (3択)

**(ii) 条件付きで可能。** 次のマイルストーンにそのまま差し込める規模ではない
(400〜800 行、`.mfrac` v2 化と全 digest の再ベースラインを伴う、この領域で 3 回目の
大規模改修)。一方で、実現不可能というわけでもなく、具体的な設計 (候補面交点の事前計算と
3 箇所のクリップの共通化) まで見えている。条件は:
- 実行中の再分割 (B) に着手するタイミングで、B が実際にこの前提を必要とすると分かった時点で
  専用のマイルストーンとして起こす (今 v1 の機能 — 事前焼き・破断・6 挙動・スキン化・ABI —
  はいずれも幾何的な閉じ (体積保存 + ベクトル面積 ≈ 0) で十分に機能しており、位相的な閉じを
  今すぐ必要とする消費者が無い)
- `.mfrac` の版上げと既存 digest の再ベースラインを受け入れる (v1 資産は当面存在しないため
  移行コストは小さいが、実装時点で存在する `.mfrac` 資産があれば焼き直しが必要になる)
