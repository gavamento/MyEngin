# M88 デバイス消失 (DEVICE_REMOVED / RESET) の検出・安全停止・復旧 — 仕様書

- slug: m88-device-lost-recovery
- 状態: 確定 (2026-10-07、planner 裁定。AskUserQuestion 不可のため [ユーザーに聞ける] 項目は司会経由で確認待ち。答えで変わるのは 7. に記載)
- 依頼原文: A5の復旧まで実装

## 1. 目的 (なぜ作るか)

GPU ドライバのリセット (TDR)・ドライバ更新・外部 GPU の取り外しで D3D11 デバイスが消失すると、
現在は `C:\HAL\MyEngin\src\Engine\Renderer\Device\SwapChain.cpp:185-192` の `SwapChain::Present` がログを
1 行出すだけで、以降は消えたデバイスへ描画を投げ続ける (画面は黒/固まり、エディタの未保存編集は失われる)。
AGENTS.md §3.4「一部の失敗で正常な機能まで使用不能にしない / 再初期化・再生成を行えるようにする」と不一致。

達成したい状態:
1. デバイス消失を**必ず検出**し、消えたデバイスへの描画を止める。
2. **描画系だけを作り直して**続行する。シミュレーション (ECS・物理・スクリプト・replay) は一切影響を受けない。
3. 作り直せなかったときは、**エディタの編集内容を退避保存し、理由を表示して終了**する (失敗の局所化と、データ損失の防止)。
4. 実機の TDR を待たずに、この経路を**決定的に何度でも**試せる (疑似消失の入口)。

## 3. スコープ

- やる:
  - 消失の検出 (Present / フレーム末)、消失後の描画停止
  - 疑似消失の入口 (CLI `--simulate-device-lost <frame>`、エディタのメニュー項目)
  - 復旧: デバイス・スワップチェーン・ImGui・シェーダ・描画パス・パス群・UI/VFX/粒子・RT・Probe/EnvMap・compute runner・アセット (メッシュ/テクスチャ/マテリアルの GPU 側)・エディタのビュー RT とプレビューキャッシュの再生成
  - 旧デバイス参照数ゲートと、ゲート不合格・再作成失敗・短時間の連続消失での①フォールバック
  - ①: エディタの退避保存、理由のメッセージ表示、非 0 終了 (Editor / Runtime)
  - 回帰テスト (SelfTest + 疑似消失付きの実行)、ADR-026、`docs/test_checklists.md` の手動 TDR 手順

  - ABI 変更 (DLL/C# への消失通知 API)
  - GPU 上にしか無い中身の保存・復元 (TAA 履歴、GPU 粒子の現在状態、compute バッファの中身)。作り直し後は初期状態から
  - ProjectManager のミニループの復旧
  - 復旧中の進捗 UI (描画できないので出せない。ログのみ)
  - D3D12 化、マルチ GPU 切り替え
- 後回し:
  - DLL/C# への `OnDeviceRestored` 通知 (要望が出たら ABI v28 で)

## 4. 仕様

### 4.1 振る舞い

#### 4.1.1 状態機械 (EngineLoop が持つ、描画専用の状態)

```
Running ──(検出)──> Lost ──(フレーム頭のセーフポイント)──> Recovering
Recovering ──(成功 + ゲート合格)──> Running
Recovering ──(再作成失敗 / ゲート不合格 / 連続消失)──> Fatal (= ①)
```

- 検出 (Running → Lost):
  - `SwapChain::Present` が `DXGI_ERROR_DEVICE_REMOVED` / `DXGI_ERROR_DEVICE_RESET` を返した。
  - または、フレーム末で `ID3D11Device::GetDeviceRemovedReason() != S_OK`。
  - または、疑似消失が指定フレームに達した (Present の判定直前で上記と同じ扱いにする。実デバイスは生きている)。
  - 検出時に 1 回だけ `MYE_LOG_ERROR` で HRESULT と removed reason (疑似なら「simulated」) を出す。
- Lost の間: そのフレームの残りの D3D 呼び出し (描画・Present・ImGui 描画) はしない。**tick は通常どおり進める** (sim は描画と独立)。
- Recovering はフレーム頭のホットリロードと同じセーフポイント (spec 5.3 フェーズ 2 付近) で同期的に実行する。非同期化しない (決定性とデバッグ性のため)。
- Recovering の手順 (順序は既存の終了順 `EngineLoop.cpp:2952-2967` と起動順 L256-332 に揃える):
  1. 非同期テクスチャ読み込み等、GPU オブジェクトを作り得るワーカーを止めて排出する。
  2. GPU を持つ全所有者に GPU オブジェクトを手放させる (Shutdown または「GPU 側だけ解放」)。CPU 側データ (メッシュの positions/indices、テクスチャの再生成レシピ、ECS) は保持。
  3. IEngineApp に `OnDeviceLost` 相当の通知 (エディタの RT / プレビューキャッシュ / ImTextureID を手放す)。
  4. `ClearState` / `Flush` の後、コンテキスト・スワップチェーン・デバイスを解放し、**旧デバイス参照数ゲート** (4.1.4) を判定。
  5. 新デバイスを**消失前と同じ種類** (HW / WARP) で作成。失敗したら待って再試行 (4.1.3)。
  6. スワップチェーン → ImGui → シェーダ → パス群 → UI/VFX/粒子 → アセット GPU 再アップロード → RT/Probe/EnvMap/compute の順に再生成。
  7. IEngineApp に `OnDeviceRestored` 相当の通知 (エディタの RT 等を作り直す)。
  8. `MYE_LOG_INFO` で「device recovered (所要 ms、試行回数)」を出し Running へ。
- Fatal (①): 4.1.5。

#### 4.1.2 疑似消失

- CLI `--simulate-device-lost <frame>`: 描画フレーム番号 `<frame>` で 1 回消失したことにする。Editor.exe / Runtime.exe の両方で有効。値が不正 (非数・負) なら起動時にエラーログを出して無視。
- CLI `--simulate-device-lost-fatal`: 疑似消失と組み合わせ、復旧を試みず①へ進ませる (①の経路を自動テストするため)。
- エディタのメニュー (既存のデバッグ系メニューの下) に「デバイス消失を偽装」項目。押した次のフレームで消失扱い。
- 疑似消失は Debug/Release の両方で使える (`_DEBUG` で分岐しない)。sim 状態に触れないので AGENTS §4.3 に抵触しない。

#### 4.1.3 再試行と打ち切り (名前付き定数にする)

- 新デバイス作成の再試行: 最大 `kDeviceRecreateAttempts = 10` 回、間隔 `kDeviceRecreateRetryMs = 500` ms (TDR 直後はドライバ再初期化中で作成が失敗し得るため)。全部失敗 → Fatal。
- 連続消失: 直近 `kDeviceLostWindowSec = 60` 秒以内に `kDeviceLostMaxInWindow = 3` 回目の消失 → 復旧を試みず Fatal (復旧直後に毎回落ちるドライバ/シェーダの無限ループを防ぐ)。
- 実時間の使用は描画専用の判断なので許可 (sim に持ち込まない)。

#### 4.1.4 旧デバイス参照数ゲート

- 手順 4 で旧デバイスを解放する前に、検査用に 1 参照だけ持ち、他の全参照が手放された後の参照数を測る (`AddRef`/`Release` の戻り値)。
- 期待値は「検査用の 1 のみ」(sub-02 で HW と WARP の両方で実測して確定する。D3D/DXGI 内部が別の参照を持つと分かったら、その値を根拠付きで定数化する)。
- 期待値より多い = どこかが旧デバイスの子オブジェクトを握っている → **Fatal へ落とす** (古いリソースを掴んだまま新デバイスで描くと未定義動作になるため)。ログに残参照数を出す。Debug 構成でデバッグレイヤが有効なら `ID3D11Debug::ReportLiveDeviceObjects` も出す (ログのみ、状態は変えない)。
- このゲートは全構成で常に判定する。
- **この性質により、②の途中のコミットでは「未対応の所有者が残る → ゲート不合格 → ①」となり、壊れた描画は出ない。** これがサブ間の安全な停止点の根拠。

#### 4.1.5 Fatal (①)

- 以降 D3D を一切呼ばない。
- IEngineApp に致命通知。エディタは:
  - 開いているシーンの**編集状態** (Play 中なら Play 開始前の状態) を、元ファイルを上書きせずに退避ファイルへ保存する。退避先はプロジェクト配下の既存の書き出し用ディレクトリ規約に合わせ coder が決めて sub に記録する (例: `<Project>/Saved/DeviceLost/<シーン名>_<YYYYMMDD-HHMMSS>.scene.json`)。未保存変更が無くても保存する (再現用)。
  - 保存失敗は理由をログとメッセージに含めるが、終了は続行する。
- メッセージボックス (Win32 `MessageBoxW`、所有窓はメインウィンドウ) で、理由 (HRESULT / removed reason / 疑似かどうか / ゲート不合格の残参照数)、退避ファイルの絶対パスを表示。文字列は `Tr()` (`C:\HAL\MyEngin\src\Engine\Core\Localization\Localization.h:32`) で日英両方を用意。`Tr()` の結果を書式文字列にしない。
- `--selftest` / `--maxFrames` 等の非対話実行中は (既存の非対話判定に従い) メッセージボックスを出さず、ログだけ出す。
- 終了コードは専用の非 0 値 (`kExitCodeDeviceLost`、既存の終了コードと衝突しない値) で終了する。終了処理は既存の Shutdown 列を通すが、GPU 解放の失敗で落ちないこと。

### 4.2 データ・保存形式・互換性

- シーン・アセット・replay・snapshot の保存形式は変えない (SimSnapshot v39 のまま、ABI v27 = 158 のまま、TypeId 追加なし)。
- 退避ファイルは通常のシーン保存と同じ形式・同じシリアライザ。
- アセットの再アップロードは AssetID を変えない。CPU 側に保持する再生成レシピ:
  - メッシュ: 頂点 (`MeshVertex` 全体。ボーン index/weight を含む) とインデックス。既存の `positions/normals/uvs/indices` で足りない分だけ足す。
  - テクスチャ: 作成元の種類ごとに — ファイル (パス + srgb)、エンコード済みバイト列 (コピー保持)、RGBA8 (コピー保持 + mips/srgb)、単色 (色)。ファイルからの再読込はディスクの現内容を読む (ホットリロードと同じ扱い)。
  - マテリアル: GPU 側 CB (`SurfaceMaterialState::perMaterialGpuCB`) は CPU 側 `perMaterialCB` から作り直す、または再ビルド扱いにする。
- メモリ増: 頂点・エンコード済み画像の CPU 保持ぶん。実測値を sub-03 の SELF_EVAL に記録する (demo シーンと三校の代表シーン 1 つ)。

### 4.3 UI / ビジュアル

- 復旧成功時: 消失フレームから復旧完了まで画面が止まる (描けないため) → 復旧後は消失前と同じ見た目に戻る。TAA 履歴・GPU 粒子・compute の中身は初期状態から再開 (数フレームで収束/再発生)。
- 復旧中の進捗表示は出さない (描画不能)。ログに開始/完了/所要時間。
- Fatal 時: メッセージボックス 1 枚 (4.1.5)。
- エディタのメニュー項目「デバイス消失を偽装」(Tr 日英)。

### 4.4 非機能

- 決定性: 復旧は ECS・RNG・物理・スクリプト・入力レーン・replay 記録に触れない。復旧前後で World のハッシュが同じ (受け入れ 9)。replay 検証中の疑似消失で検証が一致 (受け入れ 10)。
- `_DEBUG`/`NDEBUG` で sim を変えない。デバッグレイヤ依存の処理はログのみ。
- `/fp:precise` 等のビルド設定は変えない。
- レイヤ: 状態機械と再生成の手順は Engine 層 (EngineLoop)。生の D3D 型を Renderer より上に新たに露出しない (旧デバイス参照数の測定は GraphicsDevice の中に閉じ、結果を整数で返す)。Editor は IEngineApp の仮想関数経由でだけ関わる。
- 性能: 平常時のコストは Present の戻り値判定とフレーム末の `GetDeviceRemovedReason` 1 回のみ。CPU 側保持のメモリ増は 4.2 で実測報告。
- 復旧の所要時間はログに出す (シェーダ再コンパイルがキャッシュから引けるかで大きく変わるため、実測を sub-02 で記録)。

## 5. 受け入れ条件

1. Present が DEVICE_REMOVED/RESET を返すか `GetDeviceRemovedReason != S_OK` のとき、そのフレーム以降消失扱いになり、HRESULT と reason が 1 回ログに出る。 — コードレビュー + 疑似消失実行のログ
2. `--simulate-device-lost <frame>` と `--simulate-device-lost-fatal` が Editor.exe / Runtime.exe で効き、不正値はエラーログで無視される。 — Runtime.exe の実行ログ
3. Fatal 経路: Runtime.exe `--simulate-device-lost 30 --simulate-device-lost-fatal` が `kExitCodeDeviceLost` で終了し、30 フレーム以降 D3D 呼び出しをしない (D3D デバッグレイヤのエラーが出ない)。 — Debug ビルドの実行ログと終了コード
4. エディタの Fatal 経路で、開いているシーンが元ファイルを変えずに退避ファイルへ保存され、その退避ファイルをエディタで開くと元の編集状態が復元される。Play 中に消失した場合は Play 前の状態が保存される。メッセージに理由と退避パスが出る (非対話時はログのみ)。 — SelfTest (保存と再読込の一致) + 手動 1 回
5. 復旧経路: Runtime.exe でデモシーン (または coder が選ぶ代表シーン) を `--simulate-device-lost 30` 付きで実行すると、ログに「device recovered」が出て、旧デバイス参照数ゲートが合格し、指定フレーム数まで走って 0 で終了する。HW (ローカル) と `--warp` の両方で。 — 実行ログ
6. 復旧後のスクリーンショットが、消失なしの同条件実行のスクリーンショットと一致する (TAA・GPU 粒子など履歴依存の要素は無効化したシーン/設定で比較し、許容差は 0 を目標、0 にできない場合は理由と値を SELF_EVAL に明記)。 — `--screenshot` 2 本の img-diff (Editor.exe の img-diff を使う。memory: screenshot-probe-recipes)
7. 同じ実行の中で疑似消失を 2 回 (別フレーム) 起こしても 2 回とも復旧する。60 秒以内に 3 回目で Fatal に落ちる。 — 実行ログ (疑似消失の複数指定が要るなら CLI を拡張してよい)

## 7. 未決事項・リスク

ユーザーに確認したい点 (planner が裁定済み。答えが逆なら記載の影響):
- U1 [ユーザーに聞ける] プロセス内復旧 vs「退避保存 → 同じシーンで自動再起動」。裁定: プロセス内復旧 (依頼どおり)。逆を選ぶと sub-02〜05 が「再起動 1 サブ」に置き換わり、受け入れ 5〜12 が消え、代わりに「再起動後に同じシーン・同じカメラで開く」が入る。
- U2 [ユーザーに聞ける] Play 中に Fatal になったときの退避内容。裁定: Play 前の編集状態だけ保存。逆 (Play 中の実行時状態も別ファイルで保存) なら sub-01 に保存 1 本と受け入れ 4 の追記。
- U3 [ユーザーに聞ける] HW デバイスを作り直せないとき WARP で続行するか。裁定: 続行せず①。逆なら sub-02 の再作成手順に WARP 分岐が入り、復旧後に「WARP で動作中」を画面に出す UI (Tr 文言 + 表示) が sub-05 に増える。

技術リスク (coder が「不安・質問」で拾う):
- R1 旧デバイス参照数の期待値が HW/WARP/デバッグレイヤ有無で揺れる可能性。sub-02 の最初に実測する。揺れて安定しないなら、ゲートを「デバッグレイヤの ReportLiveDeviceObjects で子オブジェクト 0」へ切り替える案を planner に戻す。
- R2 シェーダの再コンパイル時間。キャッシュ (ShaderManager) から引けない場合、復旧に数秒〜数十秒。所要時間を記録し、許容外なら planner へ。
- R3 compute の中身はゼロから。GameLogic が「一度だけ初期化した GPU バッファ」に依存していると復旧後に結果が変わる。描画専用の用途に限られている前提 (sim がそれを読まないこと) を sub-04 で確認する。sim が読み戻しているなら決定性違反の既存問題として planner へ報告 (今回の修正範囲外)。
- R4 非同期テクスチャ読み込みワーカー (`TextureLibrary::AsyncWorker`) が D3D オブジェクトを作っている場合、復旧前の排出が必須。
- R5 ImGui の ImTextureID を保持している箇所 (エディタ内 8 箇所程度の cast) が古い SRV を握ると参照数ゲートで検出される — これは想定どおりの動作で、sub-05 で潰す。
