## 1. 目的と合意事項

ソース管理画面とアセットブラウザーから、右クリックでファイル・フォルダのGit操作を行えるようにする。履歴とブランチにも操作を追加し、既存規範に沿ったアイコンで操作と状態を判別できるようにする。

| 項目 | 合意した仕様 |
|---|---|
| 基本操作の対象 | ソース管理の変更一覧、アセット一覧のファイルとフォルダ |
| 追跡解除 | ローカルファイルを保持し、追跡解除のみ／追跡解除とignore追加を選択可能 |
| メニュー | ステージ、ステージ解除、差分、変更破棄、追跡解除、ignore追加、パスコピー |
| 履歴 | SHA・件名コピー、コミット差分、ブランチ作成、soft/mixed reset、revert、cherry-pick |
| ブランチ | 名前コピー、作成、切替、ローカルブランチの名前変更・安全な削除 |
| 履歴変更の開始条件 | 未保存内容と、未追跡を含むGit変更がないこと |
| アイコン | 現在のFont Awesome 6、共通UI部品、テーマの意味色を使用 |
| 対象外 | hard reset、強制ブランチ削除、force push、独自画像アイコン |

resetは選択コミットそのものへHEADを移す。revertは対象コミットを打ち消す新しいコミットを作成し、cherry-pickは対象コミットの変更を現在のブランチへ適用する。ファイルの「変更破棄」とコミットのrevertは、UI名称・内部操作名・確認文言を区別する。

## 2. 現状と責務境界

現在の変更一覧にはステージ、ステージ解除、変更破棄のボタンがあり、フォルダ選択は配下の変更行を選択する仕組みになっている。アセットブラウザーには既存の右クリックメニューとGit状態バッジがある。Git操作はEditorのセッションからRustサービスへ要求し、作業ファイルが変わる操作はGitTransactionの確認・変更分類・再読み込み経路を通す。

変更一覧だけでは、変更のない追跡済みファイルを列挙できない。アセット一覧からの追跡解除では、Gitのindexを問い合わせて追跡状態と関連ファイルを取得する必要がある。既存のmerge/rebase状態検出だけでは、revert/cherry-pickの中断状態を扱えないため拡張する。

## 3. 右クリック・対象選択の仕様

### 3.1 基本操作

| 操作 | 対象と有効条件 | 実行後の期待結果 |
|---|---|---|
| ステージ | ステージ可能な変更・未追跡ファイル | 関連ファイルも既存規則でstageし、状態更新 |
| ステージ解除 | indexに変更がある対象 | 作業ファイルを保持してindexの登録変更を戻す |
| 差分 | 単一ファイル | 既存差分表示へ接続。未追跡・バイナリは理由を表示 |
| 変更破棄 | 変更のある対象、既存保護ゲートを通過 | 既存の確認と再読み込みを通す。未追跡の削除は明示 |
| 追跡解除 | index登録済みファイル | ローカル内容を保持し、indexから外す |
| 追跡解除＋ignore追加 | index登録済みファイル | 上記に加えて再追跡を抑えるignoreルールを追加 |
| ignore追加 | 未追跡ファイル、または追跡済み対象への明示操作 | 対象に限定したルールを追記 |
| 絶対パスコピー | 対象が確定している行 | 複数は改行区切りでコピー |

実行不能な項目は無効表示し、Git未接続、処理中、競合中、対象なし、未保存などの理由をツールチップで示す。読取・コピーは、書き込み禁止条件だけで一律に無効にしない。

### 3.2 選択規則

- 選択済みのファイルを右クリックした場合は現在の選択全体を対象にする。
- 未選択ファイルを右クリックした場合は、そのファイルだけを選択して対象にする。
- フォルダ右クリックは配下を対象にする。変更一覧では配下の変更行、アセット一覧ではGit側の列挙結果を使用する。
- 複数対象の一部だけが操作可能な場合は、対象となる件数と除外理由を表示する。確認なしに一部を黙って処理しない。
- 単一ファイル差分は複数選択時に無効にする。フォルダ差分専用UIは追加しない。
- メニューを開いた時点の対象パスを保持し、一覧更新で別の対象へ入れ替わらないようにする。実行直前に対象と状態を再検証する。

## 4. 追跡解除とignore追加

### 4.1 対象列挙と関連ファイル

Gitのindexとstatusから、対象の追跡状態・変更状態を取得する。フォルダでは追跡済みと未追跡を区別し、対象をリポジトリ相対パスで整列・重複排除する。追跡解除対象はindexに存在するものだけに限定する。

本体と既存の関連ファイルを既存のPairRuleに沿って束ねる。追跡解除のために.metaを新規生成しない。関連ファイルだけが変更一覧に出ている場合や、本体が変更なしの場合も追跡対象の取得結果から補う。フォルダ自身の関連ファイルが既存規則上存在する場合も対象へ含める。

対象はGitルート内に限定する。パスはUTF-8・ルート相対・スラッシュ区切りで伝達し、絶対パス、親ディレクトリへの脱出、不正なパスを拒否する。パス指定には既存のliteral pathspec方式を使い、ワイルドカードや先頭の記号をGitオプションとして解釈させない。

### 4.2 確認・実行

追跡解除の確認画面には、対象の絶対パスと開けるリンク、用途、対象件数、関連ファイル、次回コミットでGit上の削除になることを表示する。ローカルファイルは保持されること、ignoreなしの場合は未追跡として再表示されることを明記する。

確認後に `git rm --cached` 相当の操作を行い、強制オプションは使用しない。indexと作業ファイルに不整合がありGitが拒否する場合は、先にコミットやステージ解除が必要であることを表示する。既存のステージ済み変更を自動的に取り消さない。

複数バッチの途中で失敗した場合、更新済み対象・未処理対象と最新statusを返し、部分完了を表示する。成功したように一覧を消すだけの処理は禁止する。

### 4.3 .gitignore

- 追加先はリポジトリルートの.gitignore。存在しない場合は作成する。
- ファイルはルートからの対象パス、フォルダはルートからの対象フォルダに限定したルールを追加する。フォルダ外の関連ファイルは個別ルールで補う。
- Gitignoreの特殊文字・先頭記号・空白を適切にエスケープし、意図した対象だけが無視されることを検証する。
- 既存バイト列、コメント、BOM、改行形式を保持し、必要な改行と不足ルールだけを追記する。新規ファイルはUTF-8で作成する。
- 同一ルールは重複追加しない。既存の否定ルールとの関係を確認し、追加結果はGitの判定で確認する。
- 追跡済みファイルへのignore追加だけでは追跡が解除されないため、その旨と追跡解除操作を案内する。
- 確認開始から実行直前までのディスク上の.gitignoreの変更を検出し、変更時は実行を止めて再確認を要求する。外部エディタの未保存内容は検出対象ではない（ユーザー確認済み）。.gitignore自体の追跡解除・ignore対象化は無効にする。
- 「追跡解除＋ignore追加」は事前検証後に追跡解除、続いてignore書き込みを行う。後半が失敗した場合は追跡解除済みであることを明示し、自動ロールバックや自動ステージを行わない。

## 5. 履歴・ブランチ・性能比較

### 5.1 履歴の参照

履歴行の右クリックで完全SHAコピー、件名コピー、コミット差分、当該コミットからブランチ作成を提供する。コミット差分は対象コミットと第1親の比較とし、初回コミットは空ツリーとの比較にする。マージコミットの参照差分は第1親との差分であることを表示する。

新しいコミット差分は既存の差分表示の制限・読取専用表示を踏襲し、バイナリや表示量制限を案内する。非同期応答には対象SHAを保持し、選択変更後の古い応答で現在の表示を上書きしない。

### 5.2 履歴の変更

| 操作 | 具体的な効果 | 保護 |
|---|---|---|
| soft reset | HEADを選択コミットへ移動。indexと作業ファイルを保持 | 元HEAD・新HEAD・ステージに残る変更を確認 |
| mixed reset | HEADとindexを選択コミットへ戻す。作業ファイルは保持 | 元HEAD・新HEAD・未ステージ／未追跡になる対象を確認 |
| コミットrevert | 選択コミットを打ち消す新規コミットを作成 | 適用対象と変更予測、作成結果を表示 |
| cherry-pick | 選択コミットの変更を現在のブランチへ適用 | 適用対象と変更予測、作成結果を表示 |

開始には最新のstatusで未追跡を含む変更がないこと、未保存文書がないこと、既存の再生・ビルド等の書き込み阻害条件がないこと、進行中Git操作がないことを要求する。通常のローカルブランチ上でのみ許可し、detached HEADでは理由を表示して停止する。revert/cherry-pickはGitのユーザー情報も検証する。

確認画面を開いた後にHEAD・index・作業ファイルが変わった場合は実行せず、再確認を要求する。確認には完全SHA、件名、変更ファイル、影響、元HEADによる復旧手順を表示する。追跡上流があるresetでは、通常pushが拒否される可能性を案内するがforce pushは追加しない。

マージコミットのrevert/cherry-pickは親選択が必要なため今回無効にする。空の適用などGitが完了できなかった場合は成功扱いにせず、現在の状態と中止方法を示す。

soft/mixed resetは作業ファイルを保持するため不要なアセット再読み込みを行わず、HEAD・index・履歴・ブランチ・状態表示を更新する。revert/cherry-pickは実際に変更されたファイルをGitTransactionへ渡し、既存の段階分類と再読み込み・再起動確認を適用する。

### 5.3 競合・継続・中止

merge/rebaseに加え、CHERRY_PICK_HEAD、REVERT_HEAD、sequencerの進行状態を検出し、監視対象へ追加する。現在の操作種別をセッションへ保持し、競合画面の名称と継続・中止コマンドを操作別に切り替える。

既存の競合解決経路を再利用し、継続時は当該Git操作のcontinue、中止時はabortを実行する。作成コミットのメッセージ入力で外部エディタ待ちにならないようにする。競合発生直後、継続後、中止後の実ファイル変更を再分類して反映する。

未解決中は通常のstage/commit/checkout等を既存の競合モードと同様に制限する。競合画面からの解決用ステージ操作は許可する。外部Git操作やEditor再起動後にも進行状態を再取得し、継続・中止へ戻れるようにする。中止失敗時は競合モードを維持して原因を表示する。

### 5.4 ブランチ

名前コピー、当該ブランチを起点にした新規作成、既存の保護付き切替、ローカルブランチの名前変更、マージ済みブランチ削除を提供する。

作成・名前変更はGitのブランチ名検証を通し、既存名との衝突を拒否する。別worktreeで使用中の対象は変更・削除を拒否する。名前変更はローカル参照を対象とし、リモート名を変更しない。

削除は対象ブランチ名・完全参照・用途・削除理由・影響・復旧用先端SHAを確認し、明示承認後に非強制削除を実行する。削除対象は現在のHEADへマージ済みのローカルブランチだけとする。現在ブランチ、未マージ、リモートブランチは無効にする。Gitが追加条件で拒否した場合も強制へ切り替えない。

### 5.5 性能比較Gitline

右クリックで「比較の基準に設定」、SHAコピー、件名コピー、コミット差分を提供する。既存の「選択コミットが基準、現在HEADが比較先」を保持する。履歴変更操作はソース管理画面へ集約し、性能比較画面から実行しない。リポジトリの接続先が異なる場合はそのGitlineのリポジトリを使用し、開いているゲームプロジェクトへ誤って要求しない。

## 6. アイコンとローカライズ

現在のFont Awesome 6、EditorWidgets、ScmBadgeColorを正本として使用する。独自の色定数、画像アセット、フォント、固定のボタン高さを追加しない。規範で判断できないデザインが必要になった場合はユーザーへ質問する。

| 操作・意味 | グリフの選定方針 |
|---|---|
| ステージ／解除 | PLUS／MINUS |
| 追跡解除 | LINK_SLASH |
| ignore | BAN |
| 差分 | FILE_LINES |
| 履歴 | CLOCK_ROTATE_LEFT |
| ブランチ | CODE_BRANCH |
| コピー | COPY |
| revert・変更破棄 | ARROW_ROTATE_LEFT。文字ラベルで操作を区別 |
| 通信・更新 | 既存の矢印・更新グリフを再利用 |

状態アイコンの意味と色の表は共通のEditor部品に集約する。Modifiedは編集、Addedは追加、Deletedは削除、Renamedは移動、Untrackedは未登録、Conflictは警告を表す既存グリフを選び、既存の状態文字も併記する。既存のSuccess、Warning、Error、Prefab、TextDisabledによる色を維持する。

メニュー・ボタンはアイコンと文字を併記する。追加文字列はLocalizationTable.inlとTr()を使用して日本語・英語を埋め、###識別子と書式指定子を整合させる。Tr()の結果をprintf書式へ直接渡さない。既存の選択IDを翻訳やグリフ変更で変えない。

## 7. 内部インターフェースと実装順序

### 7.1 操作インターフェース

Editor内で共通の操作種別・選択対象・確認用プレビューを持ち、ソース管理とアセットUIはそれを要求する入口とする。プレビューにはGitルート、対象パス、関連ファイル、操作可能／除外の理由、元HEADを保持する。

Rustサービスへ次の能力を追加する。操作名は既存命名に合わせ、C++定数とRust dispatcherを同時更新する。

- 対象列挙: ファイル／フォルダの追跡状態、status、関連対象を確定する読取要求。
- 追跡解除・ignore: 確認済みパス、ignore併用有無を受け取り、処理結果と最新statusを返す書込要求。
- コミット差分: 完全SHAを受け取り、差分本文と表示量制限情報を返す読取要求。
- 履歴操作: 完全SHAとsoft/mixed/revert/cherry-pickの明示的種別を受け取る書込要求。
- ブランチ作成拡張・名前変更・削除: 検証済み参照と名前を受け取る書込要求。
- 状態取得拡張: revert/cherry-pickを含む操作種別を追加し、継続・中止を正しい経路へ振り分ける。

成功・失敗どちらでも現在の状態を更新できる応答にする。部分完了は処理済み／未処理を区別する。ファイル変更を伴う操作は、開始前と実行後の実際の変更集合を保持してGitTransactionへ渡す。merge/rebaseの既存フィールドは意味を変更せず、新規フィールドを追加する。

既存仕様ではop・フィールド追加だけでプロトコル版を上げない。既存C ABIやフィールド意味を変更しない方針とし、未知opを返す古いDLLでは機能利用不能と更新案内を表示する。無反応や成功扱いにしない。

### 7.2 実装順序

1. 現在のGit状態と関連仕様を再確認し、既存のCI・性能スクリプト変更を保護する。
2. 検証用リポジトリで対象列挙→単一ファイル追跡解除→status反映の最小経路を通す。
3. 関連ファイル、フォルダ、ignore、確認・部分失敗を追加してRust/C++回帰検証を通す。
4. 共通の基本操作処理を両画面の右クリックへ接続する。既存ボタンと同じ経路に統一する。
5. 履歴の読取操作とブランチ作成・名前変更・安全な削除を追加する。
6. soft/mixed reset、revert/cherry-pick、進行状態検出、競合継続・中止・再起動復帰を追加する。
7. 性能比較Gitlineの参照操作、共通アイコン、翻訳、狭幅レイアウトを仕上げる。
8. 必須検証と実画面確認を行い、仕様文書と実装・検証記録を更新する。

新規C++ソースを追加した場合のみgen_project_files.ps1で一覧を更新する。仕様変更は既存のGit連携仕様へ反映し、アーキテクチャ判断を変更した場合はADRも更新する。docsへの実装記録では計画・実装・テスト・実画面確認を区別する。

## 8. 検証と受け入れ条件

### 8.1 機械的な検証

| 分類 | ケースと期待結果 |
|---|---|
| 選択 | 単一・複数・未選択右クリック・フォルダ。表示した対象と実行対象が一致 |
| 追跡対象 | 変更なしの追跡済み、本体無変更／関連だけ変更、未追跡混在、存在しないパスを適切に分類 |
| パス | 日本語、空白、角括弧、先頭記号、深いフォルダ、リポジトリ外入力。別対象を操作しない |
| 追跡解除 | 内容・サイズ・関連ファイルが保持され、indexからのみ外れる。強制が必要な状態は失敗 |
| ignore | 特殊文字、既存否定ルール、重複、BOM、改行、末尾改行なし、新規作成。既存内容を保持 |
| 部分失敗 | 途中のGit失敗、ignore書込不可。処理済み範囲と最新状態を明示 |
| 排他 | 連打、別画面からの同時要求、確認中の外部変更。二重書込と対象すり替わりを防ぐ |
| reset | softはindex・作業内容保持、mixedはindex更新・作業内容保持。履歴・状態表示が一致 |
| コミット適用 | revert/cherry-pickの正常・競合・空適用・mergeコミット拒否。成功と中断を区別 |
| 競合復旧 | 解決・継続・中止・中止失敗・Editor再起動。状態とディスクが一致 |
| ブランチ | 作成起点、名前衝突、不正名、未マージ、現在使用中、別worktree使用中、削除とSHAからの復旧 |
| 互換性 | 古いDLLの未知op、欠落した追加状態フィールド。失敗理由を表示し既存機能を保護 |
| アセット更新 | 実変更集合が既存分類へ渡り、必要な再読み込み・再起動確認が動く |

### 8.2 実行するチェック

- Rustの既存テストと追加回帰テスト: `cargo test --manifest-path tools/collab/Cargo.toml`。
- コラボレーションの実Git経路: `tools\collab_verify.bat` と検証用fixtureでの追加操作検証。
- C++/Rust定数・レイヤー・翻訳等のルール: `tools\check_rules.ps1`。
- Debug/Releaseのx64ビルド、両構成の `Editor.exe --selftest`。
- GitTransactionと再読み込みの拡張を含むため、`tools\replay_verify.bat` による回帰検証。
- 実行できないチェックは理由と残るリスクを記録し、成功扱いにしない。

### 8.3 実画面での確認

検証用プロジェクトをEditorで開き、変更一覧とアセット一覧の右クリックから実操作する。日本語・英語、使用可能なテーマ、狭いドック幅とウィンドウリサイズで、メニュー・ボタン・状態文字・アイコン・無効理由が読めることを確認する。

追跡解除確認の取消しではindexと.gitignoreが変化しないことを確認する。操作後の一覧と差分、履歴、ブランチが更新されること、競合中に継続・中止へ到達できることを確認する。性能比較は基準選択と分割領域のドラッグを維持する。

画面キャプチャと、使用した検証用リポジトリ・SHA・操作・期待結果・実結果をdocsへ残す。ビルド、SelfTest、Replayの成功だけではUI操作の成功を保証しない。

## 9. 作業範囲と完了報告

今回の文書作成はこの計画ファイルのみを追加する。計画の保存を機能実装の完了と扱わない。

機能実装時も、既存の未コミット変更を取り消し・上書きせず、実リポジトリで追跡解除、ブランチ削除、reset、revert、cherry-pickを試さない。検証対象の削除が必要な場合は、絶対パス・リンク・用途・理由・影響を提示して明示許可を得る。

機能の完了報告には、変更内容と理由、影響範囲、実施した検証、実画面の証拠、未検証事項、更新した文書を記載する。コミットやpushはこの文書作成の範囲に含めない。
