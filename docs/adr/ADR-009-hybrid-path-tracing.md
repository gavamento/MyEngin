# ADR-009: ハイブリッド・リアルタイムパストレーシング (RT GI / RT 影 / RT 反射)

## 決定

- **一次光線はラスタのまま**、二次光線 (拡散 GI / 平行光の影 / スペキュラ反射) だけを
  レイトレで置き換える。Deferred の G-Buffer をレイの出発点に使う (`gbPosition` は
  R16G16B16A16F のワールド座標なので、深度からの再構成が不要)
- **API は D3D11 cs_5_0 + 自前の BVH トラバーサル**。DXR / `RayQuery` は使わない
- 既定はすべて off。**off のときは既存の描画経路と 1 ビットも変わらない**ことを受け入れ基準にする
- 乱数は GPU 完結の状態レスハッシュ (PCG3D) とし、**リプレイ決定論の対象外**に置く
  (ADR-008 の GPU パーティクルと同じ扱い)
- デノイズは SVGF (テンポラル蓄積 → 分散推定 → A-Trous) を GI / 反射で共有し、
  影だけは履歴を持たない空間フィルタにする

## 理由

### なぜ DXR ではなく自前トラバーサルか

`GraphicsDevice` は Feature Level 11_0 のみを要求する設計 (対応 GPU の幅を優先) で、
DXR は D3D12 かつ FL12_0 以上が要る。エンジンの下地を D3D12 へ載せ替えるのは M46 の
範囲を大きく超えるため、**cs_5_0 のコンピュートシェーダでソフトウェア BVH を歩く**一択だった。
副作用として、BVH の構築・トラバーサル・レイ/三角形交差をすべて自分で書くことになり、
ポートフォリオとしてはむしろ中身が見える構成になっている。

### なぜ既存の BVH ビルダを流用したか

物理の `MeshColliderLibrary::BuildMeshColliderData` が既に
「決定論的な median-split・葉あたり 8 三角形・selftest 済み」の BVH を作っていた。
これを BLAS ビルダとして流用し、**新規に書いたのは TLAS だけ**にした。
GPU へ焼くときに三角形を `triOrder` の順に並べ替え、葉が連続範囲を直接指す形にしている
(葉は `left = -(triStart + 1)` の符号エンコード)。

### なぜ「demodulated (アルベドを掛けない) 出力」なのか

GI パスが返すのは**入射放射輝度**であって最終色ではない。合成側で
`gi * albedo * kD` として使う。cosine 重点サンプリングの pdf と、
このエンジンが拡散項で 1/π を省いている規約がちょうど相殺し、
throughput がアルベドの積になる — 結果として GI の出力が **IBL の irradiance と同次元**に載る。
だから IBL 拡散項を GI で差し替えても明るさに段差が出ない (実測 -0.8%)。
反射も同じ理由で demodulated にしてあり、`RtReflWeight(roughness)` による
IBL へのフォールバックが原理的に連続になる。

### なぜ影だけテンポラル履歴を持たないか

GI は低周波なので数十フレーム積んでも破綻しないが、**影は動く物体に貼り付く**ため
履歴を持つとゴーストが致命的に見える。太陽の視半径 (0.265°) はコーンが十分狭く、
1spp のノイズが半影の数画素に限られるので、分離型の空間フィルタだけで足りると判断した。

## 実装メモ

- レイヤ分離: Renderer 層は `RtSceneBindings` (SRV の束) 越しにシーンを受け取るので、
  Engine 層の `RtScene` を知らない
- インスタンスは `worldToLocal` のみ持ち、**方向ベクトルを正規化しない**。
  これで t がワールド距離のまま比較でき、TLAS/BLAS 間で単位が揃う
- `ShaderManager` に `#define` 注入口が無いため、品質分岐はすべて**定数バッファの uniform 分岐**
- 合成は `common.hlsli::ApplyLightingHybrid` を新設 (既存 `ApplyLighting` は 1 文字も変えない)。
  直接光は式を複製せず、`ApplyLighting` を「環境項ゼロ」で呼んで `Lo` だけ取り出す —
  Forward と Deferred のライティングが構造的に一致し続ける
- 自己発光 (M46i) は `Material::emissiveIntensity` (スカラー) 1 本で
  ラスタとレイトレの両方を駆動する。Deferred は G-Buffer の空いていた
  `gbMaterial.b` へ `intensity / kEmissiveMaxIntensity` で正規化して詰め、
  レイトレは `RtMaterial.emissive = linear(baseColor) * intensity` を持つ。
  **同じ強度から「発光面がラスタで明るく見えること」と「その面が GI 光源になること」の
  両方が出る**ので、見た目と光り方がずれない
- C++/HLSL で共有する定数 (`kRtStackDepth` / `kRtMaxVisit` / `kRtTemporalMaxHistory` /
  `kRtAtrousRadius` / `kEmissiveMaxIntensity`) は `tools\check_rules.ps1` の規則 9 が
  静的に一致を検査する
- HLSL の数式は `RtMath.h` / `RenderTypes.h` に CPU ミラーを置き、selftest で境界値を固定

## 決定論との関係

レイトレは**描画専用レーン**であり、ワールドハッシュにも sim にも一切関与しない。
乱数は `(ピクセル, フレーム番号)` からの状態レスハッシュで GPU 内で完結し、
CPU へのリードバックが無い — したがって ADR-004 のリプレイ一貫性契約に抵触しない
(ADR-008 の GPU パーティクルと同型の判断)。
実測でも、M46 の全サブを通して**変更前に記録した golden.rep が Debug/Release とも
600 tick VERIFY PASS** し、ReplayFile のバージョン bump は 1 度も発生していない。

スクリーンショット / リプレイ実行では乱数を自動で凍結する (`rtFreezeSeed`) ため、
同一条件の 2 回実行で PNG がバイト一致する。凍結中は毎フレーム同じ 1 サンプルを積むだけに
なるので、蓄積のデノイズ効果を計測したいときは `--rt-anim-seed` で自動凍結を解除する。

## 計測 (RTX 3060 / 1600x900 / Release、GI と反射は内部 1/2 解像度・影はフル解像度)

`[rt]` ログの GpuTimer は**最終フレーム 1 サンプル**なので分散が大きい。
下表は同一条件 5 回の**最小値**。

| パス | 既定デモ (522 インスタンス / 24 三角形) | RT ショーケース (11 インスタンス / 780 三角形) |
|---|---|---|
| BVH 構築 (CPU) | 0.20 ms | 0.02 ms |
| 拡散 GI (1spp) | 0.48 ms | 1.50 ms |
| テンポラル蓄積 | 0.04 ms | 0.06 ms |
| SVGF (分散 + A-Trous ×3) | 0.31 ms | 0.49 ms |
| RT 影 (トレース + フィルタ) | 0.34 + 0.15 ms | 0.27 + 0.22 ms |
| RT 反射 (トレース + デノイズ) | 0.48 + 0.26 ms | 0.12 + 0.37 ms |
| **GPU 合計** | **約 2.1 ms** | **約 3.0 ms** |

インスタンス数が 1/50 なのにショーケースの GI が 3 倍重いのは、
**閉じた箱では全てのレイがジオメトリに当たり、2 バウンス目と NEE の影レイまで必ず走る**ため。
開けた既定デモではレイの大半が空へ抜けて早期に終わる。
つまりこのトラバーサルのコストを支配しているのは三角形数ではなく**レイの平均行程**である。

## トレードオフ / v1 の制限

- **スキンメッシュと半透明は BVH に載せていない** — 影も落とさず、映り込みもしない
- **二次ヒットのシェーディングはマテリアル定数のみ** — D3D11 にバインドレスが無く、
  ヒットしたメッシュのテクスチャを引けない。テクスチャを持つ面は baseColor の色で映る
- **オブジェクトのモーションベクタが無い** — テンポラル再投影はカメラ運動のみを扱うので、
  動く物体にはゴーストが出る
- **ローカルライトの RT 影は無し** (ラスタとパリティ)
- GI / 反射は内部解像度からのバイリニア引き上げ (バイラテラル アップサンプル無し) で、
  シルエット際がわずかに滲む
- 鏡の中に鏡は映らない (二次ヒットの鏡面は環境近似)
- Forward パスと AssetPreview では自動的に無効 (`RtScene*` が null になる)
- 自己発光は**スカラー強度 × baseColor** なので、ベース色と違う色で光らせられない。
  Deferred では 8bit へ量子化されるため上限 `kEmissiveMaxIntensity` (=8)・刻み 8/255
  (Forward は定数バッファ直渡しで量子化なし)
