# ADR-007: Forward / Deferred の二本立てと実行時切替

## 決定
レンダリングパスは `IRenderPath` 抽象 (収集 → ソート → 提出モデル) の背後に置き、
Forward と Deferred の両方を実装して実行時に切り替え可能にする。

## 理由
- 仕様策定時の [TBD] に対し「両方を選択可能に」というプロジェクト方針決定
- パーティクルの CPU/GPU 切替と同型の「同一入力・二実装・実行時比較」構成であり、
  ポートフォリオの説明軸が揃う
- ライティング計算を common.hlsli の共通関数に置くことで、切替時の見た目を一致させ、
  シェーダホットリロードの依存グラフにも両パスが自然に乗る

## 実装メモ
- GBuffer は albedo (RGBA8, a=ジオメトリマーク) + ワールド法線 (R10G10B10A2) + 共有深度。
  ライトが平行光 + アンビエントのみなので位置再構成は不要
- 透明物とパーティクルは両パス共通の Forward 後段 (Deferred はライティング解決後に上描き)
- 検証: M6 のリプレイハッシュが Deferred でも PASS —
  「描画パスの変更はシミュレーションに影響しない」ことの回帰証明

## トレードオフ
- パス毎の状態/シェーダ管理が二重になる (共有は CB レイアウトと common.hlsli に限定)
- Deferred の利点 (多光源) は現行ライトモデルでは活きない — 拡張余地として保持
