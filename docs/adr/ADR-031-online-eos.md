# ADR-031: オンライン (ロビー・P2P 中継・無線ボイス) をホスト兼サーバ + EOS で組む

- 状態: 採用 (2026-10-14、M93)。EOS 実装は SDK v1.19.2.1 でコンパイル済み、**EOS のサービスとの疎通は未確認** (下の「未検証」)
- 出所: 宇宙服穴ゲーム (`C:\HAL\就プレ作品`) を 4 人協力で Steam 販売するための不足機能の洗い出し。
  ユーザー決定「通信の入口まで EOS」「無線だから全員に聞こえてよい」「ハーネスを使わず直接実装」。
  設計書は `plans\m93-eos\design-draft.md` (7 章に実装時の変更)

## 背景

M81 (ADR-022) で入力確定型の専用サーバ (Server.exe) とクライアントの予測ロールバックはできたが、
NAT 越え・マッチメイク・暗号化・音声は対象外にした。友人 4 人が集まるには次が要る。

- 参加の入口 (誰かが部屋を作り、他の人がそこへ入る)
- 家庭の回線どうしで繋がること (NAT 越えと、越えられないときの中継)
- ボイスチャット (このジャンルの標準装備)
- サーバ費用を毎時払わないこと (少人数開発で発売後の運用費を抱えない)

## 決定 1: ホスト兼サーバ。ホストの PC が Server.exe を子プロセスで動かす

部屋を作った人 (ホスト) の Runtime が、自分の PC で Server.exe を `--loopback --exit-when-empty` で起動し、
自分も普通のクライアントとして `127.0.0.1` へ繋ぐ。他の参加者のパケットは、ホストの Runtime が
オンラインサービスの P2P から受けて、参加者ごとのローカル UDP ソケットからサーバへ中継する。

```
ホスト:   自分の Runtime ─UDP─ 127.0.0.1:P ─ Server.exe (子プロセス、ジョブで道連れ)
          参加者 X ─P2P─ ホストの Runtime ─UDP (X 専用ソケット)─ 127.0.0.1:P
参加側:   自分の Runtime ─UDP─ 127.0.0.1:B (中継) ─P2P─ ホスト
```

- サーバから見ると、参加者ごとに別の宛先から来る普通のクライアント。ServerSession / ClientSession /
  プロトコル / `.rep` は 1 バイトも変えていない。M81 の検証 (server_verify、`.rep` の照合) がそのまま効く。
- ホストのクライアントも Hello → 確定の経路を通るので、ホストだけが有利になることはない (入力遅延は全員同じ)。

却下:
- **同じプロセスで ServerSession と HeadlessSim を回す**: HeadlessSim は 1 プロセスに複数立てられるが、
  物理ライブラリ・アセットのキー解決・C# ホストの注入先がプロセス共有で、tick ごとに `Activate()` で
  付け替える必要がある。EngineLoop の世界には付け替えの口が無く、取り違えると静かに壊れる。
  子プロセスならサーバが落ちてもホストの描画は残る (障害の局所化)。
- **GameLift の専用サーバへ全員が繋ぐ**: 公平で強いが、時間課金と、ゲームセッションを作る仲介役が要る。
  Server.exe / GameLift の経路は残し、将来選べるようにしてある。

## 決定 2: オンラインサービスを抽象 (IOnlineService) の裏に置き、EOS を第一実装にする

`IOnlineService` はログイン・ロビー (作成 / 参加コードで検索して参加 / 退出 / メンバー)・P2P データグラム・
ボイス (送信の on/off、相手ごとのミュート、発話中) だけを持つ。実装は 2 つ。

- `EosOnlineService` (Epic Online Services): Device ID で Connect にログイン (Epic アカウント不要)、
  ロビーの属性 `JOINCODE` で検索、P2P は SDK の NAT 越え + リレー、ロビーの RTC ルームでボイス。
  無料。Steam 販売でも使える。
- `LocalOnlineService`: 同じ PC の別プロセスをループバック UDP で繋ぐ開発用の代役。EOS 無しで
  ロビー → 接続 → 中継の流れ全体を実プロセスで検証でき、selftest と CI もこれで回る。

EOS を選んだ理由: ロビー・P2P・ボイスが 1 つの SDK に揃い、アカウント不要で、C SDK で自作エンジンから使える。
Vivox は位置音声が楽だが入口 (ロビー・NAT 越え) を別に要る。Steam Voice は取り込みとコーデックだけで、
送受信と空間化が全部エンジン側になる。Discord Social SDK は音声の正式提供を確認できなかった。

## 決定 3: ボイスは無線。距離減衰なしで全員に聞こえる

ユーザー決定。ロビーの RTC ルームに全員が入り、位置は送らない。常時送信が既定で、
`voice.pushToTalk` で「押している間だけ送る」へ切り替える。押下は表示レーンの生入力から読み、
`InputSnapshot` には載せない (載せるとボイスの操作で `.rep` の中身が変わる)。
エンジンのミキサー (XAudio2) へは繋がない。SDK が自前でマイクとスピーカーを扱う。

## 決定 4: EOS SDK はコミットしない

公開リポジトリでの SDK の再配布可否は開発者契約に依る。`external\eos-sdk\` は gitignore (BUILD.md だけ版管理) で、
`build\Common.props` が `Include\eos_sdk.h` の有無を見て `MYE_HAS_EOS` を立てる。SDK が無ければ EOS 実装は
空の翻訳単位になり、CI はそのままビルドできる。EOS の名前は `Online\Eos\` と `Common.props` だけ (check_rules 規則 13-d)。

## 決定 5: sim との境界

オンラインの値 (人数、表示名、発話中、P2P の到着順と時刻) は sim の外。sim へ入るのは、ホストの Server.exe が
確定入力 (Join / Leave の SystemInputTick) へ変換した後だけ (ADR-022 決定 2 のまま)。`Online\` は規則 13-a で
sim 側から include できない。サービスは出力レーン (EngineLoop のフレーム後半) で回し、接続の開始はフレーム境界。

## 結果

- 実行中にロビーから接続を始められる (`StartClient`。起動時の `--net-connect` も同じ関数を通る)。
  参加スナップショットを受け取る前に失敗したらオフラインの世界へ戻り、参加後に終わったら世界を止める
  (世界はセッションのものなので、1 人用として続けると他の人の分が宙に浮く。1 人で遊ぶには再起動)。
- P2P の 1 パケットの上限 (1,170 B) を超える確定パケットは、中継層で最大 4 断片に分ける (プロトコルは変えない)。
- ゲームのスクリプトは ABI v30 の `OnlineMemberCount` / `OnlineMemberName` / `OnlineMemberFlags` / `OnlineJoinCode` で
  ロビーを読める (HUD の名前・発話中の表示用)。値は `NetRuntimeInfo` の写しで、`Net*` と同じく表示専用。
  ミュートと退出はロビー窓だけが行い、スクリプトからは書けない (sim 側から出力レーンへの書き込み口を増やさない)。
- Runtime は普段 ImGui を持たないが、オンラインのときだけロビー窓 (ImGui の小窓) を出す。ゲーム用の見た目は
  uGUI の InputField (M75h) の後で置き換える。
- 検証: `local` で 2 プロセスを繋ぎ、2 つのクライアントの `.rep` が重なる 600 tick × 4 レーンで一致、
  参加側の `.rep` の単独再生が PASS。server_verify (A / B) PASS で既存の経路を壊していない。

## 未検証 / 既知の制限

- **EOS 実装は SDK v1.19.2.1 でコンパイルは通ったが、EOS のサービスとの疎通 (ログイン・ロビー・P2P・ボイス) は未確認。**
  設定が空なら理由をログに出してオフラインで動くことだけ確かめた。疎通の手順は `docs\eos-setup.md`。
- ホストの移譲は無い。ホストが抜けるとセッションは終わる。
- セッションが終わった後に 1 人用へ戻るには再起動が要る。
- Editor には組み込んでいない (Editor の NetWindow は起動し直す方式のまま)。
- ロビー窓に文字を打っている間、そのキーはゲームにも届く (Runtime の ImGui は入力を奪わない)。
