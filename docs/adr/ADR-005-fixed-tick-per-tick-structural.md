# ADR-005: 固定 60Hz tick と「tick 末」での構造変更適用

## 決定
シミュレーション全体を固定 60Hz tick (accumulator 方式、最大 5 tick/frame) で進める。
構造変更 (AddComponent/RemoveComponent/Destroy/SetParent) の一括適用は、仕様書 5.3 の
「フレーム末 (フェーズ 7)」ではなく **各 tick の末尾** に行う。

## 理由
- リプレイ再現 (spec 11.3) は tick 列として成立させる必要がある。フレーム末適用だと
  「1 フレームに何 tick 走ったか」(= 実行環境のフレームレート) が構造変更の適用タイミングを
  変えてしまい、Debug/Release でハッシュが一致しなくなる
- tick 末適用なら、フレーム分割と無関係に「tick N の構造変更は tick N 末で適用」が常に成り立つ

## トレードオフ
- 高負荷時は追いつけない分の実時間を捨てる (スローモーション化を許容) — tick 爆発よりも
  決定論と安定性を優先
- 描画は最新 tick の状態をそのまま表示 (補間なし)。必要になれば後続で補間を検討
