# ADR-019: モデル由来サブアセットのキーを `.meta` の GUID にする — 絶対パスを ID から追い出す

- 状態: 採用 (2026-09-12、M74a〜M74b)
- 出所: 三校 (Shadow_Sound) の 2 台運用で起きた実害。`C:\HAKtokyo\Shadow_Sound` と
  `C:\HAL\Shadow_Sound` に clone した 2 台が同じ stage1 を触った結果、シーンに
  「こっちのパス由来の ID を持つ屋根なしステージ」と「向こうのパス由来の ID を持つ屋根付きステージ」が
  同居し、**それぞれのマシンでは自分が置いた方だけが描画された** (敵も同じ)。ログは 1 行も出ない。
- 関連: M30c (`assetkey::Resolve` = パス → GUID のフック)、M39a (`assetguid::ResolvePath` = 逆方向)、
  M51b / M51j (クックキャッシュと封印)、M66 (`plans\quiet-merging-harbor.md` 決定 2 と 12 — 当時は
  「全員同じパスに clone」のチーム規則で回避し、相対化は独立マイルストーンへ送っていた)。
  仕様の本文は `engine_spec.md` §10.2.1。

## 決定

### 決定 1: 接頭辞は `"guid://" + Resolve(NormalizePathKey(modelPath))` の 16hex

メッシュ / マテリアル / スキン / 埋め込みテクスチャの登録名は `"guid://<16hex>#mesh3#part0"` の形に
する。16hex は `assetkey::Resolve` の値 = 同伴 `.meta` の GUID。作るのは
`assetkey::SubAssetKeyPrefix` の 1 本だけで、FBX / glTF の 6 か所の `pathUtf8` はすべて
`LoadContext::keyPrefix` に置き換えた。サフィックス (`#mesh%u#part%zu` など) は変えない —
変える理由が無く、変えると移行の対応付けが element_id の読み直しに依存してしまう。

却下:
- **assets ルート相対パス** (M66 の計画に書かれていた案)。clone 先の違いは消えるが、プロジェクト内で
  モデルを移動するたびに ID が変わる (M30c がファイル単位の ID で解決した問題が、サブアセットにだけ残る)。
  ローダはルートを受け取っていないので全経路に引数を足すことになり、assets の外 (selftest の一時
  コピー) には相対形そのものが無い。
- **全員同じパスに clone する規則のまま**。規則を破っても何も起きず (canonicalRoot の警告はトースト
  1 枚)、壊れ方は「相手のモデルが黙って消える」なので、破られたことに誰も気付けなかった。実際に破られた。

### 決定 2: `.meta` の無いモデルは path-hash に落ちる。ここは直さない

resolver 未設定 (`--selftest`) や `.meta` の無いファイルでは、16hex が従来の path-hash になる。
その ID はチェックアウト先に依存するが、`.meta` の無いアセットは他のすべての ID (テクスチャ /
プレハブ / physmat) も同じ条件で依存しているので、サブアセットだけ特別扱いする理由が無い。
代わりに「モデルの `.meta` はコミットする」を前提として明記し (CLAUDE.md)、
三校の `mkstage.py` は `.meta` が無ければ止まるようにした。

### 決定 3: 旧 ID は明示した旧 clone 先から再計算して、テキストのまま書き換える

`Editor.exe --migrate-subasset-ids [--project DIR] [--legacy-root OLD]... [--dry-run]`。

- ハッシュは逆算できないので、旧 ID は「保存したマシンの clone 先」を知らないと作れない。
  現在の clone 先は自動で含め、他のマシンのルートは `--legacy-root` で渡す。2 台分を 1 回で揃えられる。
- 全モデルをヘッドレス登録して新しい登録名を列挙し、`guid://<16hex>` を「旧ルート + assets 相対の
  現在位置」の正規化パスに置き換えて旧 ID を作る。glTF の `#img:` は名前の無い画像で材質キーを丸ごと
  埋め込むので、接頭辞は全出現を置き換える。
- JSON はパースし直さず、**文字列リテラルの外の非負整数トークンだけ**を置き換える。エンジンの dump と
  Python の書き出しで浮動小数の綴りが違うファイルが混ざっていても、差分が ID の桁だけに収まる
  (エンジン同梱プレハブの 288 箇所と、三校の 7 文書 1870 箇所のうち同じ作業で手を入れた stage1 以外の
  6 文書で、git の差分行数 = 置換数だった)。
- 保存後にモデルがプロジェクト内で移動していた ID は対応付けられない (相対位置が変わっている)。

却下: **ロード時に旧 ID を自動で読み替える**。現在のパスの旧 ID は計算できても、他のマシンのパスは
分からないので肝心の 2 台運用が救えない。加えて sim が触る AssetRef (Collider.meshAsset はハッシュ対象)
をロード経路で書き換えると、同じシーン JSON から始めた 2 台のワールドハッシュが「読み替え表の有無」で
割れる。

### 決定 4: 上げる版は `kCookVersion` だけ

cooked blob はキー文字列をそのまま持って Replay で登録し直し、ヘッダの検証はキーの中身を見ない。
上げないと旧形式のキーが再生され、新形式のシーン参照が全部空振りする。`.mcvx` (凸包表のキーも
登録名) も同じ版で落ちる。
シーン文書 / `.rep` / スナップショットの版は上げない — レイアウトは変わっておらず、コミットされた
リプレイもハッシュ期待値も無い (replay_verify は毎回録り直す)。

## 結果

- 三校: 別の絶対パス (空白入り) に複製したプロジェクトで、stage1 の見下ろしと敵の寄りの 2 枚が
  元の場所の撮影と **maxDiff=0** で一致した (複製側はコールドクック、元はウォーム再生)。
- 移設が ID を変えなくなったので、封印キャッシュ (M51j) は「参照の正しさ」の仕組みではなくなった。
  再パースの回避と DDS 一括後の元画像不在のために残る。
- `ConvexCookSourcePath` は `'#'` の手前をパスとして切り出していた唯一の消費者で、GUID →
  `assetguid::ResolvePath` に置き換えた。resolver が無いと「その場生成」に倒れる (正しさは同じ)。
- 他のマシンは、エンジンを更新してビルドし直すまで新しい ID のシーンを表示できない。移行後のシーンを
  古いエンジンで保存すると、その保存で置いたモデルだけが旧形式になる。
