# 物理・リプレイ・ネット・ホットリロードの経緯
コードのコメントから移した経緯。コードには今の事実と罠だけを残している。

## HotReload/DllReloader.cpp — 失敗した DLL の mtime を記録する
- (M70e) 三校プロジェクトで、旧 ABI (v15) の DLL を v16 のエディタが拒否した。Update() は 500ms ごとに棚 (cache\hot\p<pid>\vN) へ DLL+PDB を複製してから失敗し続け、51 秒で 101 段 / 63MB を積んだ。counter_ も進むので、偽の「ホットリロードしました (vN)」トーストも出続けた。そこで失敗した mtime も記録し、書き直されるまで再試行しない形にした。

## HotReload/DllReloader.cpp — ProbeWritable の共有モード
- (M52h の後) シャドウコピーの棚は M52h の p<pid> 分離でコピー先の衝突が解決していた。しかしコピー元 (ビルド出力) のプローブが排他オープンのまま残っていた。このため、ネットの 2 プロセス同時起動で互いのプローブが衝突した。負けた側は C++ スクリプト 0 本の世界で開始し、開始ワールドハッシュ照合で接続拒否になった (net_verify case A/D のフレーク)。GENERIC_READ + FILE_SHARE_READ に変えて直した。

## Physics/PhysicsSystem.cpp — 接触ソルバの蓄積インパルス化 (M59g1)
- (M28b) 以前の作りは次のとおり。
  - 速度ソルバの反復のたびに CollideManifold を呼び直していた (8 回)。押し出しも同じループで 8 回行っていた。
  - 点毎の法線インパルスは 1/count に緩和した Jacobi だった。
  - 摩擦は毎反復その場の滑り方向で測り、上限はその反復ぶんの法線インパルスだった。
  - 毎反復ゼロから解き直す方式なので、緩和が効いていた。
- (M59g1) 蓄積インパルス + クランプに改めた。蓄積の前提は「接触点が反復をまたいで同じ」なので、マニフォールド生成を 1 ステップに 1 回にし、接線も生成時に固定した。tick あたりのコストは下がった (生成 1 回 + 位置補正 8 回)。次の 2 点は M28b のまま変えていない。
  - 解き方の形 (中央法線 → 点毎 Jacobi → 重心摩擦)
  - 物理モデル (mu = sqrt(mu_a * mu_b) / e = min / kRestitutionVelThreshold / kPenetrationSlop)
- (M59g1) 点ごとの Gauss-Seidel へ作り替える案は採らなかった。warm starting 無しではスタックが歩く (3 段タワーの 600 tick ドリフトが 0.7mm → 75mm) ため。warm starting は M59h の計測ゲート付きの別コミットに回し、M59g1 では蓄積とクランプだけを足した。
- (M59g1) 蓄積インパルスのまま 1/count 緩和を残すと、4 点マニフォールドでは毎反復 1/4 しか進まない。このため 8 反復では 2 段タワーすら静定しなかった (実測)。緩和は外した。
- (M59g1) 位置補正を速度ソルバから分けた。分けないと 2 段タワーですら跳ね続け、下の接触インパルスが 2*m*g*dt の 2.3 倍に膨らんだ (実測)。位置補正のパス数 8 は、M28b の押し出し回数に合わせたもの。
- (M59g2) サブステップ導入時は、env が無ければ substeps=1 になり、M59g1 までと文の並びも同じ経路を通るように組んだ。

## Physics/PhysicsSystem.cpp — 採らなかった案・直したバグ
- (M60e) ブロードフェーズで、複合コライダーの子形状ごとにエントリを出す案は採らなかった。代わりに全子形状の和の AABB を 1 エントリにした。ペアキーを body ベースのままにすれば、SolidContact の意味も統合処理も触らずに済むため。
- (M59h) 眠っているペアで OnCollisionExit が誤発火する問題があった。CollisionSystem 側に「両者睡眠なら前 tick から Stay を繰り越す」規則を足す案は採らなかった。ソルバ側で眠りペアの重なりを毎 tick 確かめて報告する形にした。理由は (a) 生存確認が要らない、(b) 嘘をつかない。
- (M28d) 親付き静的コライダーを lt (LocalTransform) の直読みで判定していたバグを、ワールド姿勢で判定するように直した。

## Physics/PhysicsSystem.h — SolidContact.impulse の意味
- (M59g1) SolidContact.impulse の中身は蓄積インパルスに変わった。ただし「その tick にこのペアへ入った法線インパルスの合計」という意味は変えていないので、消費者は式を書き換えなくてよい。

## Physics/PhysMatLibrary.h — スキーマと adhesion の単位
- (M59a1) 物理マテリアル資産は、M59a1 の時点では sim から読まれていなかった。消費 (Collider.physMaterial の解決) は M59a2 から。スキーマは M59f2 (静動摩擦分離・転がり抵抗) の分まで先に定義した。後からキーを足すと、プリセットとユーザー資産の書式が二世代に割れるため。M59f2 までのソルバは動摩擦だけを使っていた。
- (M60d) 粘着力は、計画では「adhesion·面積」だった。しかしソルバは接触面積を持たない (マニフォールドは最大 4 点) ので、単位を N にした。

## Physics/PhysicsDebugDraw.cpp / PhysicsDebugDraw.h — 関節と可動域の可視化
- (M60a) 関節の可視化は、拘束ソルバと同じサブで入れた。M59 で可視化を面空力より前に置いて正解だったのと同じ判断。

## Replay/TimeTravel.h / TimeTravel.cpp — 分岐 (M72a) と置き場所
- (M52e) シークで戻った後に tick が走ると、記録済みの未来を捨てていた (OnTickEnd の縮退経路も resize で捨てていた)。分岐点の編集前と編集後も区別していなかった。編集前のスナップショットを残したまま未来を捨てていたので、後からその tick へ戻ると編集が黙って消え、その先へ戻ると HASH MISMATCH になった。M72a で、未来を分岐として残し、Fork が編集後の状態を pinned で撮り直す形にした。
- (M52e) TimeTravel は計画では src\Editor\ 配下に置く予定だった。M52f のクラッシュ用リングが同じ型を使うので、Engine 層に置いた (Editor は Engine より上位にある)。
- (M52i) OnTickEnd は、M52f までは中で HashOf を呼んでいた。クラッシュリング / ロールバックも同じ tick で撮るので、1 tick に 2〜3 回走っていた (実測 約 0.2ms/回)。M52i で、呼び出し側が撮った値を渡す形にした。

## Replay/WorldHasher.h / WorldHasher.cpp — SimSources と内容ゲート
- (M60'a、予約事項 1) SimSources を箱にしたのは、名指し引数のまま増やすと全呼び出し (~107 箇所) が毎回壊れるため。導入時のコメントは「次は M60'b の XpbdBackend」だった。その後、組み立ては SimSourcesOf の 1 か所に集めた。
- (M60'b / M65a) XPBD 池と音響の波の節は内容ゲートにした。CPU 粒子節のように「ポインタが非 null なら空でも定数を 1 個畳む」形を真似ると、配線しただけで既存シーン全部 (音響の導入時は 6 シーン) のハッシュが動き、.rep の版上げが要るため (計画の決定台帳 4)。
